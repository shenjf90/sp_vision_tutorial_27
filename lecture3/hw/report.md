## 1. 图像生命周期与所有权

解释本项目中图像源为什么会复用缓冲区，以及 `cv::Mat` 的普通复制对底层像素数据
意味着什么。说明你的修改让一个 `Frame` 在进入队列后拥有什么，并解释为何后续读取
不会再改变它。

图像源中的 `buffer_` 模拟相机 SDK 持有的采集缓冲区。每次 `next()` 读取新文件时，都会把新
像素写进同一个缓冲区，以避免相机在每一帧都重新分配内存。`cv::Mat` 的普通复制只复制矩阵头，
底层像素通过引用计数共享；因此原先把 `buffer_` 直接赋给 `frame.image` 后，旧帧会随着下一次
采集而变成新图像。

我在交付 `Frame` 前使用 `buffer_.clone()` 深拷贝像素。于是每个 Frame 自己拥有一份连续的
像素快照，`expected_checksum` 也正是这份快照的校验值。后续 `next()` 仍可覆盖源的 `buffer_`，
但已经进入队列的 Frame 不再引用它，worker 开始处理前的校验值不会被后续采集改变。

## 2. 并发处理与恰好一次

结合 `BlockingQueue` 的 `push`、`pop` 和 `close` 行为，解释多个 worker 如何分工。
为什么你的实现既不会漏掉已经入队的帧，也不会重复处理同一帧？输入耗尽时，正在等待
以及仍在处理数据的 worker 分别会怎样？

producer 为每张输入图像生成一个递增 ID 的 Frame，并以 `std::move` 交给 `BlockingQueue`。
`push` 在互斥锁内把该元素放入 FIFO 队列；每个 `pop` 也在同一把锁内取走并移除队首元素，因而
同一元素只能被一个 worker 获得。多个 worker 都循环调用 `pop`，所以它们分工处理而不会重复。

producer 读完输入后调用 `close()`。关闭并不会清空队列：只要队中仍有元素，`pop` 仍会返回元素，
故已入队帧不会遗漏。队列排空后，`pop` 返回 `false`；`close()` 的 `notify_all` 会唤醒正在等待的
worker，让它们退出循环。尚在处理某帧的 worker 则完成处理、保存和统计后，再次 `pop` 并正常退出。

## 3. 共享统计数据

指出哪些线程会读写 `Statistics`。解释原实现中的竞争为什么可能导致错误结果，并说明
你的同步方案提供了什么保证。还应说明取得快照时为什么是安全的。

producer 调用 `onProduced()`；所有 worker 分别调用 `onProcessed()`、`onSaved()`，并在校验失败时
调用 `onCorrupted()`；main 线程会通过 `statistics()` 调用 `snapshot()` 读取结果。原先的递增是
读取旧值、延迟、再写回新值的复合操作。两个 worker 同时执行时可能读取同一个旧值并覆盖彼此的
结果，快照同时读取也同样是数据竞争。

我为 Statistics 增加了一把互斥锁。每个更新在持锁状态下完成整个读改写操作，`snapshot()` 也在
同一把锁下复制四个计数。因此每次调用线性化为一次完整更新，快照看到的是同一同步点上的一致值，
不会丢失更新或读取到发生数据竞争的值。

## 4. 线程关闭协议

分别描述以下两条路径中的事件顺序，并解释为什么不会发生 `std::terminate`、悬空访问
或永久等待：

1. 调用者执行 `start()` 后显式调用 `wait()`；
2. 调用者执行 `start()` 后不调用 `wait()`，直接让 `Pipeline` 析构。

如果你的实现允许某个生命周期方法被重复调用，也请说明其行为；如果不允许，请说明前置条件。

显式 `wait()` 路径中，main 先 join producer。producer 读完输入后关闭队列；workers 因此在消费
完所有已入队帧后退出，随后 `wait()` 逐一 join 它们。线程对象均不再 joinable，调用者可安全读取
最终统计或销毁 Pipeline。

若调用者只执行 `start()` 就离开作用域，析构函数会调用同一个 `wait()`。它仍会等待 producer
关闭队列，再等待全部 worker 消费完和退出，因此不会让仍 joinable 的 `std::thread` 析构（这会触发
`std::terminate`），也不会在 worker 仍访问 `this` 时销毁成员。队列关闭会唤醒等待者，所以不会
永久等待。

`wait()` 对尚未启动或已经等待过的 Pipeline 是安全的：它只 join 仍为 joinable 的线程。`start()`
被定义为只能调用一次；重复调用会抛出 `std::logic_error`，以免在已关闭的队列上创建第二批线程。
